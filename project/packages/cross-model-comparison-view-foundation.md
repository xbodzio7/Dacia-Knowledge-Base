# Cross-Model Comparison View Foundation

Date: 2026-07-26

## Purpose

Implement the scope-preserving navigation design selected in the preceding review without changing master data, reporting scopes or comparison calculations.

## Products

The package adds two deterministic products:

- `cross-model/cross-model-comparison-view.json`;
- `cross-model/cross-model-comparison-view.html`.

The JSON is the machine-readable inventory and navigation contract. The HTML is a fully self-contained static page with no JavaScript and no runtime image dependency.

## Model-family layer

The view contains exactly five model cards:

- Sandero;
- Sandero Stepway;
- Jogger;
- Duster;
- Bigster.

Each card exposes only source-safe navigation metadata: generation, body and segment codes, active configuration and version counts, exact latest catalogue-price range with coverage, recorded seat values, transmissions, powertrain labels, model-source provenance and links to existing reporting scopes.

Bigster and Duster have no exact recorded seat values in the current catalog. Their cards therefore show `not stated`, never zero seats or an assumed five-seat value.

## Reporting-scope layer

The directory contains exactly nineteen existing scopes and all seventy-two active configurations exactly once.

Each scope card includes:

- the existing scope slug and a human-readable label;
- model family or families;
- configuration and existing pair counts;
- technical-slot count;
- exact configuration labels;
- relative links to the already generated HTML, JSON, Markdown and CSV difference reports.

The one established mixed-model scope, `sandero_ecog120_manual`, remains visibly marked and unchanged at five configurations, ten pairs and fifty-six technical slots.

## Comparison boundary

Model cards never create a pair. The view links only to reports generated by the existing `configuration_comparison_bundle` scope discovery and rendering pipeline.

The product records:

- `cross_scope_pairs_generated = false`;
- `ranking_generated = false`;
- `recommendations_generated = false`;
- `inferred_values_generated = false`.

## Release integration

The two files are added to the deterministic data-product archive and therefore to the public offline workspace. Existing shortlist and comparison-bundle members remain unchanged. The archive inventory increases from eighty-three to eighty-five members.

The release manifest records the five-family navigation product but preserves the same seventy-two configurations, nineteen scopes and one hundred fourteen within-scope pairs.

## CLI

The unified command is:

```bash
python tools/dkb.py cross-model-comparison-view \
  --json ../cross-model-comparison-view.json \
  --html ../cross-model-comparison-view.html
```

At least one output is required. Repeated generation from unchanged repository data is byte-identical.

## Data boundary

This package does not:

- change any CSV master data;
- add schema or an alternative comparison engine;
- infer missing model facts;
- normalize heterogeneous technical contexts into a common score;
- generate cross-scope pairs, winners or recommendations.
